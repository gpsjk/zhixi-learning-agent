# 知错 · 课后错题诊断与答疑智能体

基于原项目升级的本地学习工作台。保留 Streamlit、Python、SQLite 及原有模型接口，增加完整的学习与复习流程。系统架构、模块职责、数据流与验收标准见《系统方案.md》。

> 本版在上一版基础上新增两项需求：**教师端班级学情统计**与**拍照上传作业照片自动识题**。其余功能保持上一版不变。

## 启动

需要 Python 3.10 或以上；本次在 Windows / Python 3.12 下验证。

1. 完整解压压缩包，进入 learning_agent 文件夹，不要直接在压缩包中运行。
2. 双击 start.bat。首次运行会创建虚拟环境并联网安装依赖。
3. 浏览器打开后即可使用；没有自动打开时访问终端显示的本地地址，默认 http://127.0.0.1:8501。
4. 使用完毕在终端按 Ctrl+C 停止。

也可以在项目目录执行：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m streamlit run app.py
```

端口占用时，在最后一条命令后加 --server.port 8502。应用默认仅监听本机。

## 七个页面

- 学习看板：收录数量、到期任务、自评掌握数量、累计复习、学科和错误类型分布、待巩固知识点、复习活动。
- 错题诊断：最多上传 5 张作业照片并自动拆分多题；逐题核对来源、题目、作答和参考答案，可排除或合并；也可继续使用手工单题录入。
- 错题本：按关键词、学科、掌握状态和收藏筛选；分页查看解析和练习；记录反思；导出当前筛选结果；确认后删除。
- 复习训练：查看到期题或全部题；先独立作答，再核对解析和自评；保存作答与复习日期。
- 智能答疑：选择已保存的题目继续追问，保留每题独立对话；真实模型接收本题上下文和最近 12 条消息。
- 教师端：按学生、学科、时间区间汇总全班错题；给出错误最集中的知识点排行、涉及学生数、错误类型与学科分布、错题明细（含学生上传的作业原图）与汇总导出；可通过模型生成讲评课重点、课堂步骤和针对性练习。
- 使用与设置：学习流程、模型配置指引、数据备份说明。

## 拍照上传怎么用

1. 进入“错题诊断”，展开“📷 拍照上传作业（自动识别题目与作答）”。
2. 用电脑摄像头拍照，或从相册选择 JPG / PNG，合计最多 5 张。
3. 按需填写“学生姓名”与“识别用学科提示”，点击“识别照片内容”。
4. 系统自动拆分多道题；逐题核对题目、学生答案、正确答案、解题过程、学科和来源图片。误识别项可取消“包含此题”，被错误拆开的相邻内容可合并。
5. 点击“诊断并保存选中题目”。每题独立处理：某题失败时，已成功题不会丢失；修正或恢复模型后再次点击只重试未成功题。
6. 如只需处理一题，也可点击“回填第一题到单题表单”，继续原有单题流程。原照片随成功记录保存，教师端可回看。

识别只转写照片中真实可见的内容；看不清的地方会列入“无法确认”提示，不会自动补全或代做。识别需要支持图片的多模态模型，见下节。

## 教师端怎么用

1. 学生录入错题时填写“学生姓名”（留空记为“未署名”）。
2. 进入“教师端”，在筛选区选择学生、学科与统计区间。
3. “错题统计”标签页给出错误最集中的知识点、涉及学生数、错误类型与学科分布。
4. “错题明细”标签页按学生查看每道错题的原答案、诊断结论和上传的作业照片。
5. “讲评建议”标签页可让模型根据统计生成讲评重点与针对性练习。
6. “数据导出”标签页可导出统计汇总 JSON 与错题明细 CSV。

统计为本地错题记录的数量分布，受学生录入次数影响，**不等同于考试得分或能力排名**。默认排除来源为“演示数据”的记录，可在筛选区勾选包含。

## 连接模型

将 .env.example 复制为 .env，填入你自己的配置，然后重启应用：

```text
OPENAI_API_KEY=你的密钥
OPENAI_BASE_URL=
OPENAI_MODEL=你的模型名称
OPENAI_VISION_MODEL=支持图片的多模态模型名称
```

使用兼容接口时填写服务商提供的 Base URL。模型名以服务商实际支持的名称为准。密钥不写入数据库，也不会随本项目提供。

`OPENAI_VISION_MODEL` 只用于拍照识别。留空时沿用 `OPENAI_MODEL`；若该模型不支持图片输入，识别会返回可读的错误提示，其余功能不受影响。例如 DeepSeek 的对话模型不支持图片，需要另外填写一个多模态模型才能使用拍照识题。

**没有密钥也能运行，但属于演示模式。** 演示诊断是模板，演示练习为固定题库，演示答疑为引导模板；它们不能代表对输入题目的真实评阅。新记录会标明“演示数据”或“模型生成”；无法确认来源的旧记录标为“历史数据”。本次未使用真实 API 密钥进行联网模型验证。

## 复习规则

忘记 → 待复习，1 天后；模糊 → 巩固中，2 天后；掌握 → 已掌握，连续掌握时依次 3、7、14、30 天后。遗忘或模糊重置连续掌握次数。题目初次收录即进入待复习列表；已掌握题目到期后仍会再次出现。日期使用运行电脑的本地日期。

掌握状态来自学生自评，不是自动判分。图表基于实际数据库，包含演示及历史记录，不作为能力测评结论。当前训练记录对应原题，同类练习提供答案供自行核对。

## 数据保留与备份

数据位于 data/mistakes.db。修改包保留原压缩包中的数据库，不插入测试用例。首次启动会自动添加新字段和关联表；原题目、答案、诊断与练习字段保留。

备份时先关闭应用，再复制整个 data 文件夹。也可通过环境变量 LEARNING_AGENT_DB_PATH 指定数据库位置。JSON 导出只包含筛选后的题目，Markdown 导出是复习册；两者均不能代替包含全部答疑和复习流水的数据库备份。删除题目会同时删除关联复习和对话，界面要求勾选确认。

## 代码结构

```text
app.py             入口、单题诊断表单、批量照片卡片与部分失败重试
photo_pipeline.py  多题批次标准化、来源追踪、合并和提交筛选
workspace_ui.py    看板、错题本、复习、答疑、使用说明
teacher_ui.py      教师端：班级错题统计、知识点排行、错题明细、讲评建议、导出
database.py        SQLite 存储、旧数据迁移、批次幂等保存、教师端统计、照片存取
llm_service.py     模型调用、结构解析、演示模式、上下文答疑、多题照片识别、讲评建议
models.py          Pydantic 数据结构（诊断、练习、多题照片批次、讲评报告）
prompts.py         诊断、练习、拍照转写与讲评提示词
.streamlit/        主题和本地服务配置
tests/             服务、数据库、迁移、教师端统计、拍照上传及应用流程测试
```

## 验证

在项目目录执行 .venv/Scripts/python.exe -m pytest -q。详细验证结果见《验证记录.md》。测试使用临时数据库，不修改用户历史记录。requirements-tested.txt 记录本次验证使用的精确依赖版本，可用 pip install -r requirements-tested.txt 复现环境。

本版是单人本地应用，未实现登录、多用户隔离、自动评分及云端部署。教师端统计基于本机错题记录，不是考试成绩；拍照识别依赖服务商的多模态模型，字迹潦草或照片倾斜时可能识别错误，必须人工核对。模型输出及参考答案仍需结合教材核对。
